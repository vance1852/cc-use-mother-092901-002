# 司机履约与权益保障服务

面向监管机构与运输企业的货运司机履约台账与权益保障系统。它在
`transport_coordination` 基础能力（主体、幂等、SQLite 事务、哈希审计）之上，
解决两类集中投诉：

1. 司机尚未满足休息要求时平台继续派单；
2. 月末用晚到的异常记录追扣已结算运费，司机看不懂依据、也无法证明申诉期间不应继续扣款。

仅依赖 Python 标准库与 SQLite，时间全部走可替换/可手动推进的可控时钟。

## 核心机制

### 可控时钟的工时台账
- 记录驾驶、装卸、等待、场地休息、卧铺休息（双驾随车）、途中救援六类区间，
  以及换班、取消、补录、冻结四类事件。
- 原始日志事件派生出不可变的工时区段；同一时段不允许重叠记录。
- 台账可按司机冻结到某一时点：冻结关闭在途开放区段并锁定，
  **换班、取消、救援、补录只能影响尚未冻结的区段**。

### 派单前原子校验
`dispatch_trip` 在单条 `BEGIN IMMEDIATE` 事务内同时校验主驾与副驾：
- 连续驾驶是否已达上限（默认 4 小时，装卸/等待/救援不打断连续累计，
  只有达到时长的休息才打断）；
- 剩余连续驾驶容量是否足以完成本趟；
- 接下本趟后 24 小时累计驾驶（8h）与累计工时（13h）是否超限；
- 任务结束后能否落实最短休息窗口（默认 20 分钟）。

不满足时派单被拒绝并写入 `dispatch_decisions` 留痕；承运人可在明确留痕的前提下
**强制派单**（`forced=true`），监管视图据此把超时责任归为
`carrier_forced_dispatch`。监管人员不能强制派单。

### 版本化与证据关联
- 合同与规则（工时上限、最低结算、申诉时限）均为版本化数据；
- 每趟任务在创建时**快照**当时生效的规则版本，规则后续调整不改写历史任务；
- 扣款必须先登记异常证据（含异常发生时间与证据到达时间），
  超过任务完成后规定天数（默认 3 天）到达的证据禁止扣款。

### 结算、申诉与争议托管
- 运费按约定价与最低保障孰高；等待（免计 30 分钟）、装卸、救援、卧铺值守各有补贴。
- 每条结算行带稳定**幂等锚点**：同一事件重放绝不重复计费；
  账期结算可重复调用增量入账。
- 司机在申诉时限（默认结算后 7 天）内可对扣款申诉：
  **争议金额单独托管（escrow），无争议收入照常放行**；
  申诉进行中系统拒绝同一任务的新增扣款。
- 监管裁决：成立则托管金额退还司机并作废扣款，不成立则退还承运人。

### 关账与复算
- 账期关账后明细不可变，新扣款一律拒绝；
- `recompute_closed_period` 用新规则重新计算已关账账期，只生成对比记录
  （原总额、新总额、差额、逐行差异），不动原始账。
- 因申诉成立而作废的扣款是裁决结论，复算时不会复活；仍在托管中的扣款保持托管。

## 角色视图

| 角色 | 主要 API 能力 |
| --- | --- |
| 司机 `driver` | 查看可接任务（带本人实时可用性校验）、登记本人工时、本人结算明细、提交与查看申诉 |
| 承运人 `carrier` | 建任务/派单（含强制留痕）、登记证据与扣款、结算/关账、本企业数据视图 |
| 监管 `regulator` | 超时责任与强制派单归责、查看全部结算与申诉、裁决申诉、触发已关账账期复算 |
| 管理员 `admin` | 建档、合同/规则版本管理、全部数据 |

## 主要接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/bootstrap` | 初始化首位管理员 |
| POST | `/carriers` `/drivers` `/principals` | 承运人、司机、访问主体建档 |
| POST | `/contracts` `/rulesets` | 合同版本、规则版本（可多次调用产生新版本） |
| POST | `/trips` | 建任务（快照规则） |
| GET | `/availability` | 派单前只读校验剩余工时与休息窗口 |
| POST | `/dispatches` | 原子校验后派单（`force` 留痕强制） |
| GET | `/trips/available` | 司机可接任务视图 |
| POST | `/work/start` `/work/stop` `/work/intervals` | 开工/收工/整段记录（含补录 `backfill`） |
| POST | `/shift-changes` | 双驾换班 |
| POST | `/trips/<id>/cancel` `/complete` | 取消 / 完成任务 |
| POST | `/freezes` | 冻结司机台账 |
| POST | `/evidence` | 登记异常证据（含到达时间） |
| POST | `/periods` `/settlements` `/deductions` | 账期、结算、扣款 |
| POST | `/periods/<id>/close` | 关账 |
| POST | `/recomputations` | 新规则复算已关账账期 |
| POST | `/appeals` `/appeals/<id>/resolve` | 申诉 / 裁决 |
| GET | `/settlements` `/appeals` | 结算明细 / 申诉进度（按角色过滤） |
| GET | `/overtime-responsibility` | 超时责任视图 |
| GET | `/audit-events` `/health` | 审计链 / 健康检查 |

所有写接口通过 `X-Actor-Id` 标识主体，并要求 `request_id` 做幂等键；
重放同一 `request_id` 返回原始回执（被规则拒绝的派单重放仍返回拒绝）。

## 测试

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

## 离线验收

```bash
PYTHONPATH=src python3 -m driver_guarantee.acceptance
```

验收脚本在临时库中走完整链路：跨夜双驾、救援、强制派单、结算、晚到证据拦截、
申诉托管、裁决、关账、新规则复算、台账冻结，输出各项护栏布尔值与审计链校验结果。

## HTTP 服务

```bash
PYTHONPATH=src python3 -m driver_guarantee.api --database driver_guarantee.sqlite3 \
  --host 127.0.0.1 --port 8090
```
